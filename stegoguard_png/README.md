# StegoGuard PNG

**Программный комплекс информационной безопасности для автоматизированного анализа и оценки
стеганографической стойкости PNG-изображений в промышленных системах.**

Язык: Python 3.9+. Зависимости: numpy, scipy, Pillow, matplotlib (GUI использует стандартный Tkinter).

## Назначение

В промышленных системах (АСУ ТП, SCADA, HMI, системы видеоконтроля) изображения передаются между
сегментами сети: снимки технологических камер, тепловизионные кадры, экраны HMI, схемы и мнемосхемы.
PNG хранит данные без потерь, поэтому это удобный контейнер для скрытых каналов: утечки данных,
доставки команд или вредоносной нагрузки. Комплекс решает такие задачи:

1. **Обнаружение скрытых вложений**: статистический стегоанализ пиксельных данных и структурный анализ формата PNG.
2. **Оценка стеганографической стойкости** изображения как контейнера: сколько данных можно скрыть
   незаметно для средств контроля (индекс ИСС, безопасная ёмкость).
3. **Оценка живучести скрытого канала** к преобразованиям. Показывает, какие преобразования гарантированно его уничтожают.
4. **Нейтрализация (санитизация, CDR)**: очистка структуры и перезапись LSB без заметного искажения.
5. **Непрерывный контроль каталога** (шлюз приёма файлов) с карантином, журналом SQLite и отчётами.

## Установка

```bash
pip install -r requirements.txt      # или: pip install .   (появится команда stegoguard)
python run_tests.py                  # 28 автотестов
```

## Быстрый старт

```bash
python main.py                                   # графический интерфейс
python main.py samples demo --count 3            # испытательный набор с разметкой
python main.py analyze demo -o reports           # анализ каталога + отчёты HTML/JSON/CSV
python main.py robustness demo/camera_00_clean.png --attacks --report rob.html
python main.py benchmark demo                    # точность на размеченном наборе
```

## Команды

| Команда | Назначение |
|---|---|
| `analyze PATH... [-r] [--robustness] [--attacks] [-o DIR] [--formats json,html,csv] [--db] [--json] [--all-files]` | анализ файлов/каталогов |
| `robustness FILE [--rates 0.01,0.1] [--trials N] [--attacks] [--report X.html]` | оценка стеганографической стойкости |
| `sanitize IN... -o OUT [--lsb-mode predictive/random/none] [--alpha]` | нейтрализация скрытых каналов |
| `monitor DIR [--interval 5] [--quarantine Q] [--clean-dir OK] [--sanitize-dir S] [--report-dir R] [--db H.db]` | контроль каталога |
| `history [--limit] [--verdict] [--sha256]` | журнал проверок |
| `embed COVER OUT (-m TEXT / -f FILE) [-k KEY] [--method lsb_replacement/lsb_matching]` | эталонное встраивание (испытания) |
| `extract IMAGE [-k KEY] [-o FILE]` | извлечение эталонного вложения |
| `samples DIR`, `benchmark DIR`, `init-config FILE`, `gui` | служебные |

Общие параметры: `-c config.json`, `--log-level`, `--log-file`.

**Коды возврата** (для интеграции со шлюзами, SIEM, CI и сценариями АСУ ТП):
`0` вложений не выявлено, `1` подозрительно, `2` обнаружено вложение, `3` ошибка.

## Архитектура

```
stegoguard/
  png_parser.py    структурный анализ PNG (ISO/IEC 15948): чанки, CRC, IDAT/zlib, данные после IEND, сигнатуры файлов
  image_io.py      загрузка L/LA/RGB/RGBA/P/16 бит в единое представление каналов
  analysis/        статистический стегоанализ
    chi_square.py  атака хи-квадрат Вестфельда–Пфитцмана + прогрессивная кривая
    rs.py          RS-анализ (Fridrich–Goljan–Du)
    spa.py         анализ пар отсчётов SPA (Dumitrescu–Wu–Wang)
    ws.py          взвешенный стегоанализ WS (Fridrich–Goljan, Ker–Böhme)
    features.py    тест однородных областей FRN, LSB-плоскость, шум, HCF-COM, сложность
    ensemble.py    ансамбль и вероятность обнаружения
  scoring.py       интегральный риск, заключение, рекомендации
  robustness.py    оценка стеганографической стойкости (ИСС, безопасная ёмкость)
  attacks.py       живучесть LSB-канала к преобразованиям (BER)
  sanitizer.py     нейтрализация (CDR)
  embedding.py     эталонные LSB-замена/согласование с ключом (испытания и верификация)
  metrics.py       MSE, PSNR, SSIM
  analyzer.py      оркестратор анализа
  report.py        отчёты JSON / CSV / HTML с графиками
  database.py      журнал SQLite;  monitor.py  контроль каталога
  cli.py, gui.py   интерфейсы;  samples.py, benchmark.py  испытательный набор и оценка точности
```

## Методы

**Структурный анализ.** Проверяются сигнатура, порядок и уникальность критических чанков, CRC32 каждого
чанка, корректность IHDR/PLTE (в том числе дубли цветов в палитре как признак EzStego-подобных методов),
неизвестные и частные чанки, размер вспомогательных чанков, содержимое tEXt/zTXt/iTXt (Base64, hex,
высокая энтропия, сигнатуры ZIP/PDF/ELF/PE/сценариев). Поток IDAT распаковывается целиком: данные
после конца zlib-потока, избыток или недостаток относительно размера из IHDR (включая Adam7), недопустимые
типы фильтров строк. Отдельно анализируются данные после IEND. Каждая находка получает критичность
(информация / низкая / средняя / высокая / критическая) с весами 0/10/35/65/90.

**Статистический стегоанализ** по каждому цветовому каналу:
* χ²-атака: p = 1 − F(Σ(h₂ₖ − ēₖ)²/ēₖ), ēₖ = (h₂ₖ + h₂ₖ₊₁)/2. Прогрессивная кривая оценивает длину последовательного вложения.
* RS: доли регулярных/сингулярных групп (маска 0110) для M и −M на исходном изображении и с инвертированными LSB,
  затем квадратное уравнение 2(d₁+d₀)z² + (d₋₀−d₋₁−d₁−3d₀)z + d₀−d₋₀ = 0, p = z/(z−½). Считается по горизонтали и вертикали.
* SPA: ½(|W|+|Z|)p² + (2|X|−|P|)p + |Y|−|X| = 0.
* WS: p = 2 Σ wᵢ (sᵢ − s̄ᵢ)(sᵢ − ĉᵢ), wᵢ ∝ 1/(5+σᵢ²).
* FRN (тест однородных областей, для синтетического контента HMI/SCADA): в чистом изображении окна 3×3 с
  размахом ≤ 2 постоянны. При вложении с долей r доля непостоянных окон f = 1 − (1 − r/2)⁹, откуда r = 2(1 − (1−f)^{1/9}).
  Метод выявляет и **LSB-согласование (±1)**, против которого RS/SPA/WS бессильны.

Оценка доли по каналу: 0.5·WS + 0.25·RS + 0.25·SPA (или FRN, если он применим и больше).
Вероятность обнаружения задаётся логистической функцией с центром между порогами `payload_suspicious`
и `payload_stego`; также учитывается χ²-атака.
Интегральный риск: R = 100·(1 − (1 − Rстат/100)(1 − Rструкт/100)). Заключение по порогам 30/60.

**Оценка стеганографической стойкости.** В центральный фрагмент (до 512×512) встраиваются случайные
сообщения с долями r ∈ {0.5%…100%} методами LSB-замены и LSB-согласования. Для каждого r считаются
P_обн(r) ансамбля «слепых» детекторов, PSNR и SSIM. Результаты:
* безопасная доля r*: максимальное r, при котором P_обн < 0.5 для всех r' ≤ r;
* безопасная ёмкость C* = r*·N/8 байт;
* **ИСС = 100·(1 − AUC)**, где AUC это нормированная площадь под P_обн(log r). Итог берётся по наиболее
  опасному методу. Классы: ≥70 высокая, 40–70 средняя, <40 низкая.

Высокий ИСС значит, что изображение удобно как контейнер (шумные текстурированные кадры камер).
Низкий ИСС типичен для экранов HMI и схем: любое вложение в них заметно.

**Санитизация.** Удаляются все чанки, кроме IHDR/PLTE/IDAT/IEND/tRNS, и данные после IEND.
LSB перезаписываются предсказательно: новый бит выбирается так, чтобы значение было ближе всего к
предсказанию по 4 соседям, вычисленному только по старшим битам. Результат не зависит от исходных LSB,
поэтому канал уничтожается полностью (BER ≈ 0.5), а изображение не вызывает ложных срабатываний
детекторов (в отличие от случайной замены LSB). PSNR ≈ 51 дБ.

## Результаты испытаний (синтетический набор, `samples --count 5 --seed 11`, 97 файлов)

| Класс | Верно |
|---|---|
| Чистые контейнеры (камера, тепловизор, HMI, схема) | 20/20 (FPR 0%) |
| LSB-замена 10% / 40% / 100% | 45/45 |
| LSB-согласование 40% | 5/15 (выявляется на HMI, на шумных кадрах нет) |
| Данные после IEND, zTXt, частные чанки, данные после zlib-потока | 17/17 |

Accuracy 89.7%, Precision 100%, TPR 87%. Для LSB-замены граница уверенного обнаружения около 10% заполнения,
до ~5% вложение статистически незаметно. Это и отражает ИСС.

## Ограничения

* LSB-согласование (±1) в шумных естественных изображениях слепыми методами практически не обнаруживается.
  Комплекс честно отражает это в оценке стойкости (ИСС LSB-согласования ≈ 99) и рекомендует санитизацию как
  гарантированную меру.
* Адаптивные методы (HUGO, WOW, S-UNIWARD) требуют стегоанализа на машинном обучении (SRM + ансамбль
  классификаторов) и в текущую версию не входят. Санитизация уничтожает и их.
* Для палитровых изображений статистический анализ ведётся по индексам палитры, достоверность ниже.
* После санитизации изображения со вложением ±1 в однородных областях следы модификации остаются видимыми
  (сам канал при этом уничтожен).
